# Поточный шифр Salsa20

**1.1. Описание алгоритма и его реализации**

Salsa20 — это поточный шифр, который генерирует псевдослучайную последовательность байт (ключевой поток), а затем выполняет операцию `XOR` между этой последовательностью и исходным текстом. Для расшифрования выполняется та же операция с шифротекстом.

Реализация состоит из следующих ключевых функций:

*   `Encrypt(plainBytes []byte, key []byte) ([]byte, error)`
    *   **Назначение:** Основная функция для шифрования данных.
    *   **Применение:** Принимает на вход слайс байт `plainBytes` (открытый текст) и ключ `key`. Генерирует случайное 8-байтное значение `nonce` (уникальный номер для каждого сообщения). Разбивает текст на блоки по 64 байта. Для каждого блока вызывает `encodeBlock`, чтобы сгенерировать ключевой поток и выполнить XOR.
    *   **Формат вывода:** Возвращает шифротекст в формате: `[8 байт nonce] + [8 байт длина] + [шифротекст]`. Это позволяет правильно расшифровать данные.

*   `Decrypt(ciphertext []byte, key []byte) ([]byte, error)`
    *   **Назначение:** Расшифрование данных.
    *   **Применение:** Принимает на вход шифротекст в формате, сгенерированном функцией `Encrypt`. Извлекает `nonce` и исходную длину. Аналогично шифрованию, для каждого блока вызывает `encodeBlock`, который генерирует тот же самый ключевой поток (так как ключ и `nonce` известны) и выполняет XOR с блоком шифротекста. В конце обрезает расшифрованный текст до исходной длины.

*   `encodeBlock(plainBlock [16]uint32, key [8]uint32, nonce, blockIdx uint64) [16]uint32`
    *   **Назначение:** Шифрование одного 64-байтного блока.
    *   **Применение:** Это ядро алгоритма. Функция выполняет следующие шаги:
        1.  Вызывает `initState` для создания начальной матрицы состояния (ключ, nonce, константы, счетчик блока).
        2.  Вызывает `getMixedState` для выполнения 20 раундов перемешивания над копией матрицы.
        3.  Вызывает `getKeystreamBlock` для получения блока ключевого потока путем сложения исходной и перемешанной матриц.
        4.  Вызывает `xorBlocks`, чтобы выполнить `XOR` между блоком открытого текста и блоком ключевого потока.


**1.2. Описание тестов**

Для проверки Salsa20 были написаны следующие тесты:

*   **`TestEncryptDecrypt_RoundTrip`**
    *   **Цель:** Проверить симметричность операций. Убедиться, что сообщение, зашифрованное и затем расшифрованное одним и тем же ключом, полностью совпадает с оригиналом.
    *   **Как проверялось:**
        1.  Задается статический ключ и тестовое сообщение.
        2.  Сообщение шифруется функцией `Encrypt`.
        3.  Полученный шифротекст расшифровывается функцией `Decrypt`.
        4.  Результат расшифровки сравнивается с исходным сообщением. Тест считается успешным, если они идентичны.

*   **`TestEncrypt_InvalidKey`**
    *   **Цель:** Проверить, что алгоритм корректно обрабатывает ключи неверной длины (Salsa20 требует ключ 16 или 32 байта).
    *   **Как проверялось:**
        1.  Создается ключ заведомо неверной длины (например, 9 байт).
        2.  Вызывается функция `Encrypt` с этим ключом.
        3.  Тест проверяет, что функция вернула ошибку, а не `nil`.

# Блочный шифр Skipjack

**2.1. Описание алгоритма и его реализации**

Skipjack — это блочный шифр, который оперирует 64-битными (8-байтными) блоками данных. Для обработки файлов произвольной длины используется потоковый режим и стандарт дополнения PKCS#7.

Ключевые функции реализации:

*   `EncryptFile(writer io.Writer, reader io.Reader, key []byte) (int64, error)`
    *   **Назначение:** Шифрование файла (или любого потока данных).
    *   **Применение:** Читает данные из `reader` блоками по 8 байт. Каждый полный блок шифруется функцией `Encrypt` и записывается в `writer`. Когда данные в `reader` заканчиваются, последний (возможно, неполный) блок дополняется до 8 байт по стандарту PKCS#7, шифруется и записывается.

*   `DecryptFile(writer io.Writer, reader io.Reader, key []byte) (int64, error)`
    *   **Назначение:** Расшифрование файла.
    *   **Применение:** Читает зашифрованные данные из `reader`. Расшифровывает все блоки, кроме последнего, и записывает результат в `writer`. Последний блок обрабатывается отдельно: он расшифровывается, с него удаляется дополнение PKCS#7, и только после этого полезные данные записываются в `writer`.

*   `Encrypt(block [BlockSize]byte, key [10]byte) [BlockSize]byte`
    *   **Назначение:** Шифрование одного 8-байтного блока.
    *   **Применение:** Реализует 32 раунда преобразований (правила `ruleA` и `ruleB`) над входным блоком, используя 80-битный (10-байтный) ключ.

*   `Decrypt(block [BlockSize]byte, key [10]byte) [BlockSize]byte`
    *   **Назначение:** Расшифрование одного 8-байтного блока.
    *   **Применение:** Применяет инвертированные раунды (`inverseRuleA` и `inverseRuleB`) в обратном порядке для восстановления исходного блока.

**2.2. Описание тестов**

*   **`TestEncryptDecryptSymmetry`**
    *   **Цель:** Проверить корректность шифрования и расшифрования файлов для данных разной длины. Особое внимание уделяется граничным случаям, которые важны для правильной работы дополнения PKCS#7.
    *   **Как проверялось:**
        1.  Создается набор тестовых данных (`testCases`):
            *   Пустой файл.
            *   Данные короче одного блока (< 8 байт).
            *   Данные, равные ровно одному блоку (8 байт).
            *   Данные, занимающие несколько блоков, но не кратные 8.
            *   Данные, длина которых кратна 8 байтам (например, 32 байта).
        2.  Для каждого случая данные шифруются, а затем результат расшифровывается.
        3.  Итоговый результат сравнивается с оригиналом.

*   **`TestInvalidKeySize`**
    *   **Цель:** Убедиться, что функции шифрования/расшифрования файлов возвращают ошибку при использовании ключа неверной длины (Skipjack требует 80 бит, то есть 10 байт).
    *   **Как проверялось:**
        1.  Вызываются функции `EncryptFile` и `DecryptFile` с ключом неверной длины (3 байта).
        2.  Тест проверяет, что обе функции вернули ожидаемую ошибку `ErrInvalidKeySize`.

# Хеш-функция на основе Skipjack

**3.1. Описание алгоритма и его реализации**

Хеш-функция построена на основе блочного шифра Skipjack с использованием схемы сжатия Дэвиса-Мейера в рамках структуры Меркла-Дамгарда.

Ключевые функции:

*   `Hash(message []byte) [BlockSize]byte`
    *   **Назначение:** Вычисление 64-битного хеша для сообщения произвольной длины.
    *   **Применение:**
        1.  Вызывает `addMerkleDamgårdPadding` для дополнения сообщения: к нему добавляется бит `1`, затем необходимое количество нулей, а в конце — 64-битное представление длины исходного сообщения.
        2.  Инициализирует внутреннее состояние `hashState` константным вектором `IV`.
        3.  В цикле обрабатывает каждый 8-байтный блок дополненного сообщения:
            *   Текущий блок сообщения используется в качестве **ключа** для шифра Skipjack.
            *   Текущее состояние `hashState` **шифруется** с помощью этого ключа.
            *   Результат шифрования `XOR`-ится с `hashState` для получения нового состояния.
        4.  Возвращает финальное значение `hashState` в качестве хеша.

**3.2. Описание тестов**

*   **`TestAvalancheEffect` ("Лавинный эффект")**
    *   **Цель:** Проверить, что небольшое изменение во входном сообщении приводит к значительным, непредсказуемым изменениям в выходном хеше. Это ключевое свойство для криптографических хеш-функций.
    *   **Как проверялось:**
        1.  Берется исходное сообщение и вычисляется его хеш (`originalHash`).
        2.  Создается копия сообщения, в которой изменяется всего один бит (например, с помощью операции `XOR` для первого байта).
        3.  Вычисляется хеш измененного сообщения (`modifiedHash`).
        4.  Два хеша (`originalHash` и `modifiedHash`) сравниваются побитово, и подсчитывается количество несовпадающих бит (`diffBits`).
        5.  Тест считается успешным, если количество изменившихся бит превышает заданный порог (например, треть от общего числа бит, т.е. > 21 бит для 64-битного хеша). Это показывает, что изменение было не локальным, а затронуло всю структуру хеша.
